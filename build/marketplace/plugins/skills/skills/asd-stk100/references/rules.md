# ASD-STK100 규칙 전체

ASD-STE100 Issue 9(2025-01-15)의 9개 절을 한국어에 맞게 옮긴 규칙이다. 절 번호는 STE와 같다. STE 원문을 번역한 것이 아니다. 원칙만 가져와 한국어 문장에 맞게 다시 썼다.

문장 표현을 판단할 때 해당 절의 규칙·이유·예외를 함께 읽는다. 사실·범위·확신 정도와 문체의 선택은 [공통 원칙](../SKILL.md#공통-원칙)이 기준이다. 아래 예는 표현을 판단하기 위한 것이며, 그 사실이나 종결형을 결과물에 복사하는 틀이 아니다.

## 1. 단어

**1.1 쉬운 우리말을 먼저 쓴다.**
- 이유: 독자가 한 번에 뜻을 안다.
- 일본어 투 한자어와 어려운 행정 용어는 [word-list.md](word-list.md)에서 바꿀 말을 찾는다.
- 예: 금번 작업 → 이번 작업, 익일 → 다음 날, 수순에 따라 → 순서대로
- 예외: 바꿀 말이 문맥에 맞지 않거나 바꾸면 뜻이 흐려지면 그대로 쓴다. 법령이나 규격에 정의된 용어, 사물 이름도 그대로 쓴다 (법제처 『알기 쉬운 법령 정비기준』 용어편).

**1.2 한 대상은 한 용어로 부른다.**
- 이유: 용어가 바뀌면 독자는 다른 대상으로 읽는다.
- 예: "구성 파일"로 시작했으면 끝까지 "구성 파일"로 쓴다. "설정 파일", "config"를 섞지 않는다.

**1.3 한 낱말은 한 뜻으로 쓴다.**
- 이유: 뜻이 여럿인 낱말은 해석이 갈린다.
- 예: "확인한다"가 "값을 본다"인지 "승인한다"인지 모호하면 "값을 본다", "승인한다"로 나눠 쓴다.

**1.4 업계에서 굳은 기술 용어와 외래어는 그대로 쓴다.**
- 이유: 억지로 바꾼 말은 오히려 낯설다.
- 예: 서버, 배포, 커밋, 토픽, 롤백, 로컬, 캐시는 바꾸지 않는다. "로컬 드라이브"를 "지역 드라이브"로 바꾸지 않는다.
- 처음 나올 때만 풀이한다. 그 뒤로는 용어만 쓴다.

**1.5 영어 동사를 소리 나는 대로 옮기지 않는다.**
- 이유: "~되다", "~하다"를 붙인 음차어는 뜻이 흐리다.
- 예: 리턴 → 반환, 체크 → 확인, 세팅 → 설정, 콜 → 호출, 디플로이 → 배포, 어사인 → 배정. "기본값으로 폴백된다"는 "기본값으로 돌아간다"로 쓴다.
- 예외: 업계에서 명사로 굳은 말(롤백, 커밋)은 "~한다"를 붙여 쓴다.

**1.6 새로 쓸 때 모호한 낱말 대신 수치와 범위를 쓴다.**
- 이유: "적당한", "많은", "가능한 한"은 독자마다 다르게 읽는다.
- 예: 디스크 여유 공간이 충분해야 한다 → 디스크 여유 공간이 [필요한 크기] 이상이어야 한다
- 값을 모르면 지어내지 말고 빈자리로 둔다.
- 새로 쓸 때 전부 아는 목록은 다 적는다. 다 적지 못하면 문서 위치를 알려 준다.
- 번역·교정에는 [의미 보존](../SKILL.md#공통-원칙)을 적용한다. 원문의 모호함을 추정한 수치로 메우지 않는다.

## 2. 명사 나열

**2.1 명사를 셋 넘게 잇지 않는다.**
- 이유: 명사만 이어지면 무엇이 무엇을 꾸미는지 알기 어렵다.
- 예: 운영 서버 접근 권한 관리 체계 개선 → 운영 서버에 접근하는 권한을 관리하는 방식을 고친다

**2.2 "및"으로 명사구를 잇지 말고 서술어로 푼다.**
- 이유: "~ 제고 및 ~ 효율화"는 무엇을 하는지 감춘다.
- 예: 보안성 제고 및 운영 효율화를 도모한다 → 보안을 강화하고 운영 효율을 높이려 한다
- 예외: 표 제목과 목록 항목처럼 짧게 써야 하는 곳은 명사형으로 쓴다.

**2.3 긴 용어는 처음에 다 쓰고 줄임말을 붙인다.**
- 예: 특정 시점 복구(PITR)를 쓴다. 그 뒤로는 PITR만 쓴다.

## 3. 서술어

**3.1 행위자가 원문이나 문맥에 있으면 주어로 세워 능동문으로 쓴다.**
- 이유: 누가 하는지 드러나야 독자가 할 일을 안다.
- 예: 인증 모듈은 API 게이트웨이에 의해 대체된다 → API 게이트웨이가 인증 모듈을 대신한다
- 예외: 행위자를 모르거나 중요하지 않으면 피동문을 쓴다. 무생물 주어라 능동 서술어와 어울리지 않을 때도 피동문을 쓴다. "로그가 저장된다"는 그대로 둔다.

**3.2 피동을 겹치지 않는다.**
- 예: 적용되어진다 → 적용된다, 읽혀진다 → 읽힌다, 보여진다 → 보인다

**3.3 동작을 명사로 돌려 썼다면 동사로 푼다.** "진행·실시·수행"의 판단과 예외는 [번역투 T19](translationese.md#3-명사-중심-구조)를 따른다.

**3.4 "~시키다"가 실제 사동인지 판단한다.** 기준과 예는 [번역투 T20](translationese.md#1-피동과-행위자)에 있다.

**3.5 서술어를 겹쳐 쌓지 않는다.**
- 이유: "~하게 될 수 있을 것으로 보인다"는 무엇을 주장하는지 흐린다.
- 예: 처리 속도가 개선되어질 수 있을 것으로 기대된다 → 처리 속도가 개선될 수 있을 것으로 기대된다
- 겹친 층을 걷어 낸 뒤 [의미 보존](../SKILL.md#공통-원칙)을 확인한다. 위 예에서는 이중 피동만 고쳤다.

**3.6 새로 쓰는 설명에서 일반적인 동작은 현재형으로 쓴다.**
- 번역과 고쳐 쓰기에서는 완료, 진행, 계획, 추정을 그대로 둔다. "개편했습니다"를 "개편합니다"로 바꾸지 않는다.
- 예: 서버는 시작할 때 구성 파일을 읽을 것이다 → 서버는 시작할 때 구성 파일을 읽는다

**3.7 "할 수 있다"는 가능성이나 허용을 말할 때만 쓴다.**
- 이유: 규격 문서에서 "할 수 있다"는 비강제라는 뜻이다. 기계적으로 바꾸면 의미가 바뀐다.
- 예: 앞 문장이 경로 지정을 말할 때, 이를 통해 서버 동작을 제어할 수 있다 → 경로를 지정하면 서버 동작을 제어할 수 있다
- "이를 통해"만 조건으로 바꾸고 "할 수 있다"는 남긴다.
- 예외: 실제로 선택할 수 있는 기능을 설명하면 그대로 둔다.

**3.8 권고·의무 표현을 고칠 때는 의미 보존을 확인한다.** 표현별 변환은 [번역투 T18](translationese.md#4-판단과-강조)을 따른다.

## 4. 문장

**4.1 문장이 꼬일 때만 나눈다.**
- 연결 어미가 거듭되거나 부연이 끼어 있으면 주어와 서술어의 호응, 동작 순서, 조건이 걸리는 범위가 분명한지 확인한다.
- 분명하면 그대로 둔다. 흐리면 부연을 본문에 풀거나 문장을 나눈다.
- 나눌 때는 조건, 원인, 목적 관계를 드러내는 말을 남긴다. "~기 때문이다", "그러면" 같은 말이다.
- 짧다는 이유만으로 문장을 합치거나 나누지 않는다. 원문 한 문장을 이유 없이 둘로 나누지 않는다.
- 예: 이렇게 하면 서버 동작을 더 잘 제어할 수 있다. 문제 해결도 쉬워진다 → 이렇게 하면 서버 동작을 더 잘 제어하고 문제도 쉽게 해결할 수 있다 (원문이 한 문장일 때)
- 길이 기준은 8.1을 본다.

**4.2 주어와 서술어를 맞춘다.**
- 확인법: 주어와 서술어만 이어 읽는다.
- 예: 당사는 개발 주기가 빠르게 변하고 있으며 → 당사의 개발 주기가 빠르게 변하고 있으며

**4.3 누가 하는지 모호하면 주어를 생략하지 않는다.**
- 예외: 앞 문장과 주어가 같으면 생략한다.

**4.4 복잡한 내용은 세로 목록으로 쓴다.**
- 날짜, 대상, 조건처럼 나열할 정보는 목록으로 쓴다. 이유, 절차의 흐름, 예외는 완결된 문장으로 쓴다. 지나치게 줄인 개조식은 뜻을 바꾼다.
- 목록 앞 문장은 쌍점이나 "다음과 같다"로 끝낸다.
- 항목은 같은 형식으로 맞춘다. 모두 문장이거나 모두 명사형이다.

**4.5 접속어는 앞뒤 관계를 분명히 할 때 쓴다.**
- 인과, 조건, 대조, 추가 관계를 드러내는 접속어는 글을 돕는다. 국립국어원 지침과 STE 규칙 4.4도 관련된 문장을 연결어로 이으라고 한다.
- 접속어 반복과 글의 진행을 알리는 말은 [번역투 S3·T23](translationese.md#5-연결과-흐름)에서 판단한다.

**4.6 지시어는 가리키는 대상이 하나일 때만 쓴다.**
- "이는", "이를", "해당"이 무엇을 가리키는지 모호하면 명사를 다시 쓴다.
- "해당 작업"은 "이 작업"으로 쓴다.

**4.7 같은 뜻을 겹쳐 쓰지 않는다.**
- 예: 과반수 이상 → 과반수, 제출 유무 여부 → 제출 여부, 미리 사전에 → 미리, 위치하고 있다 → 있다
- 목록은 [translationese.md](translationese.md) 6절에 있다.

**4.8 이중 부정은 뜻이 같을 때만 긍정문으로 쓴다.**
- 부정의 범위와 확신 정도가 같으면 긍정문으로 바꾼다. 예: 이 옵션은 끄지 않으면 안 된다 → 이 옵션은 꺼야 한다
- 가능성을 남기는 표현은 확정적인 설명으로 바꾸지 않는다. "저장하지 않으면 적용되지 않는 것은 아니다"는 "저장하지 않아도 적용된다"와 뜻이 다르다. 뜻이 모호하면 원문을 둔다.
- 예외: 일부러 강조할 때.

**4.9 꾸미는 말은 꾸밈을 받는 말 바로 앞에 둔다.** 주어와 서술어도 가까이 둔다.

## 5. 절차문

**5.1 한 단계에 주된 동작 하나를 쓴다.** 실패 지점을 구분하려고 서비스 중지, 파일 복원, 소유자 변경, 권한 변경처럼 독립적인 상태 변경마다 번호를 나눈다. 조회·검사로 그 결과를 확인하는 일은 같은 단계에 둔다.
- 예외: 동시에 해야 하는 동작은 한 단계에 쓴다. "Shift 키를 누른 채 파일을 끈다."

**5.2 선택한 문체로 지시한다.** 문체 선택은 [공통 원칙](../SKILL.md#공통-원칙)을 따른다.
- "~한다"체 문서면 "서비스를 멈춘다", "~합니다"체 문서면 "서비스를 멈춥니다"로 쓴다. 직접 지시한다는 이유로 별도의 종결형을 선택하지 않는다.

**5.3 조건을 먼저 쓰고 동작을 나중에 쓴다.**
- 예: 복구가 끝나면 서비스를 다시 시작한다.
- 나쁜 예: 서비스를 다시 시작한다. 단, 복구가 끝난 뒤여야 한다.

**5.4 동작 뒤에 확인할 결과를 쓴다.**
- 새 절차문의 각 번호는 동작 하나 → 필요한 명령 → 확인 기준 순서로 쓴다. 같은 번호의 끝에 확인할 상태나 값을 문장으로 쓴다.
- 예: 서비스를 멈춘다. `systemctl status` 결과가 `inactive`인지 확인한다.

**5.5 참고에는 정보만 쓴다. 지시는 단계로 쓴다.**
- 이유: 참고 안에 숨은 지시는 독자가 놓친다.

## 6. 설명문

**6.1 정보를 차례로 준다.** 전체를 먼저, 부분을 나중에 쓴다.

**6.2 문단 첫 문장에 요지를 쓴다.** 나머지 문장은 요지를 받친다.

**6.3 문단 하나에 주제 하나를 담는다.** 주제가 바뀌면 문단을 나눈다.

**6.4 문단은 다섯 문장 안팎으로 쓴다.** 여섯 문장을 넘으면 나눈다.

**6.5 구조를 설명할 때는 구성 요소를 먼저 나열하고 흐름을 순서대로 쓴다.**

**6.6 문서나 기능을 주어로 쓴 문장은 서술어와 어울리지 않을 때만 고친다.**
- 그대로 둘 예: 이 문서는 배포 절차를 설명한다
- 고칠 예: 이 기능은 사용자가 로그를 검색할 수 있게 해 준다 → 이 기능으로 로그를 검색할 수 있다
- 이 항목은 공공기관 출처를 확인하지 못한 이 스킬의 규칙이다.

## 7. 안전 지시

**7.1 위험 대상과 결과를 문장으로 밝힌다.** 사람이 다치거나 서비스가 멈추거나 데이터가 사라지는 등 실제 위험을 구체적으로 쓴다.

**7.2 지시나 조건으로 시작한다.**

> 운영 데이터베이스에서 이 명령을 실행하지 않는다. 모든 테이블이 지워진다.

**7.3 위험이나 결과를 다음 문장에 쓴다.**

## 8. 문장 부호와 길이

**8.1 문장 길이**
- 글자 수 기준을 두지 않는다. 문장은 4.1에 따라 꼬일 때만 나눈다.
- 근거: 국립국어원 지침은 "한 문장에 한두 가지 정보만 담는다"고만 정하고 글자 수 기준을 두지 않는다 (국립국어원 2021). 글자 수 목표를 두면 모델이 문장을 지나치게 잘게 나누는 것을 시험에서 확인했다.

**8.2 줄표(—, ㅡ)와 그 대용을 쓰지 않는다.**
- 대용: 엔 대시(–), 하이픈 두 개(--), 띄어 쓴 하이픈( - )을 줄표처럼 쓴 것.
- 이유: 영어식 줄표 부연은 문장을 두 갈래로 나눈다. 25만 어절 영한 병렬 말뭉치에서 영어 원문의 줄표가 한국어 줄표로 옮겨진 예는 한 건도 없었다. 번역자는 대개 문장을 나누거나(40.5%) 연결 표현으로 풀었다 (김정우 2012, 『새국어생활』 22-1).
- 규정: 현행 한글 맞춤법(2015 시행)에서 줄표 항목은 부제 표시 하나다. 문장 중간에 끼어든 어구는 쉼표가 기본이고 줄표는 대신 쓸 수 있는 부호다. "ㅡ"는 한글 자모라 문장 부호가 아니다. 규범이 금지하는 것은 아니며, 이 스킬의 선택이다.
- 장황한 줄표 부연의 모양과 고친 예는 [translationese.md](translationese.md) 7절에 있다.
- 예외: 제목 뒤 부제를 표시할 때.
- 예: 토큰 갱신 로직 — 특히 만료 처리 — 을 바꾼다 → 토큰 갱신 로직에서 특히 만료 처리를 바꾼다.

**8.3 괄호에는 짧은 값만 넣는다.**
- 넣는 것: 약어의 원어, 원어 병기, 단위, 기본값, 그림·표 번호, 대안 값
- 넣지 않는 것: 설명, 이유, 예시 목록, 문장
- 예: 일부 서비스(로그인, 결제 등)가 느려진다 → 로그인, 결제 같은 일부 서비스가 느려진다
- 괄호 안의 설명과 예시 목록은 먼저 본문 구조에 넣는다. 호응이나 조건의 범위가 흐릴 때만 문장을 나눈다. 쉼표가 있다는 이유만으로 나누지 않는다.
- 예: 시간 제한(기본값은 30초이며, 0으로 설정하면 제한이 없다)을 지정한다 → 시간 제한(기본값: 30초)을 지정한다. 0으로 설정하면 제한이 없다.

**8.4 세미콜론을 쓰지 않는다.** 앞뒤 관계에 맞는 연결 표현으로 바꾼다. 호응이나 조건의 범위가 흐릴 때만 문장을 나눈다.

**8.4.1 코드·시각·실제 키와 값 표기의 쌍점은 유지한다.** `"timeout": 30`, `03:00`, `상태: 제안`처럼 값이나 형식의 일부인 쌍점을 설명용 접두사와 구분한다. 변수의 뜻을 푸는 `` `TIMEOUT`: 제한 시간 ``은 “`TIMEOUT`은 제한 시간이다”처럼 문장으로 쓴다.

**8.5 쉼표는 읽기에 필요할 때만 찍는다.** 연결 어미 뒤에 습관적으로 쉼표를 찍지 않는다.

**8.6 굵은 글씨는 제목과 화면 이름에만 쓴다.** 문장 중간을 굵게 강조하지 않는다.

## 9. 작성 관행

**9.1 낱말만 바꿔서 어색하면 문장 구조를 바꾼다.**
- 이유: 번역투는 낱말이 아니라 구조에서 생긴다.
- 예: 앞 문장이 경로 지정을 말할 때, 이를 통해 서버의 동작을 더 잘 제어할 수 있으며 문제 해결이 쉬워진다 → 경로를 지정하면 서버 동작을 더 잘 제어하고 문제도 쉽게 해결할 수 있다.

**9.2 문체와 용어를 대조한다.** 선택한 문체와 용어가 문서 전체에서 유지되는지 확인한다.

**9.3 최종본을 점검한다.** [점검과 완료 기준](../SKILL.md#점검과-완료-기준)에 따라 원문 대조와 후보 검토를 마친다.
