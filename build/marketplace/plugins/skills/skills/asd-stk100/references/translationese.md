# 번역투와 어색한 연결

영어·일본어를 직역한 문장 구조와 LLM 글에 자주 보이는 연결 습관을 정리한 목록이다. 항목 번호는 `scripts/check_style.py`의 규칙 ID와 같다. 번호가 없거나 검사 없음으로 표시한 항목은 스크립트가 찾지 않는다.

이 표는 일괄 치환 목록이 아니다. "그대로 둘 때"에 해당하면 고치지 않는다. 낱말만 바꿔서 어색하면 문장 구조를 바꾼다.

## 목차

1. 피동과 행위자
2. 조사와 전치사 직역
3. 명사 중심 구조
4. 판단과 강조
5. 연결과 흐름
6. 중복과 군더더기
7. 줄표와 장황한 부연

예 앞의 [원문]은 공공기관 자료나 논문에 실린 예다. [작성]은 이 스킬이 만든 예다.

---

## 1. 피동과 행위자

**T01 이중 피동 (~되어지다, ~여지다, 읽혀지다)**
- 고칠 때: 언제나 고친다. "~되다", "~히다"나 능동문으로 쓴다.
- 그대로 둘 때: 없다.
- [원문] 프로그램이 마무리되어진다 → 프로그램을 마무리한다 (국어원 지침 p.7)
- [원문] 문자로 쓰여진 문서 → 문자로 쓰인 문서 (법제처 문장편 p.167)
- [작성] 설정 파일은 시작 시 읽혀집니다 → 설정 파일은 시작할 때 읽힙니다

**T02 ~에 의해 (피동의 행위자)**
- 고칠 때: 행위자가 있으면 주어로 세워 능동문으로 쓴다. 수단이면 "~으로"를 쓴다.
- 그대로 둘 때: 바꾸면 뜻이 흐려지거나 원인을 나타낼 때 (법제처 문장편 p.196).
- [원문] 내외부 사정에 의해 변경될 → 내외부 사정으로 변경될 (국어원 지침 p.7)
- [작성] 로그는 관리자에 의해 주기적으로 삭제된다 → 관리자가 로그를 주기적으로 지운다

**피동문 전반** (스크립트 검사 없음)
- 고칠 때: 행위자가 사람이면 능동문으로 쓴다. 우리말은 사람을 주어로 쓰는 경향이 있다 (법제처 문장편 p.166).
- 그대로 둘 때: 무생물 주어라 능동 서술어와 어울리지 않을 때. "로그가 저장된다"는 그대로 둔다.
- [원문] 전단을 만드는 데 엄청난 노력이 기울여졌다 → 전단을 만드는 데 엄청난 노력을 기울였다 (김순영 2012)

**T20 ~시키다**
- 고칠 때: 스스로 하는 일에 "~시키다"를 붙이면 "~하다"로 쓴다.
- 그대로 둘 때: 남에게 시키는 일. "직원을 교육시킨다"는 문맥에 따라 둔다.
- [작성] 응답 속도를 향상시킨다 → 응답 속도를 높인다

**문서·기능 주어 + 행위** (스크립트 검사 없음)
- 문서나 기능이 주어인 문장은 [문장 규칙 6.6](rules.md#6-설명문)에서 주술 호응과 유지할 예를 확인한다.

## 2. 조사와 전치사 직역

**T03 ~에 있어(서)**
- 고칠 때: 추상적인 대상이나 상황 뒤의 "~에 있어(서)"를 "~에서", "~할 때", "~하는 데"로 쓴다.
- 그대로 둘 때: 위치나 존재를 뜻하는 "있다". "파일이 서버에 있어 복사한다"는 그대로 둔다. 스크립트는 둘을 가르지 못한다.
- [원문] 시설물에서 촬영함에 있어서 → 시설물에서 촬영할 때 (국어원 지침 p.7)
- [작성] 배포 자동화에 있어서 가장 중요한 것은 롤백이다 → 배포를 자동화할 때는 롤백이 가장 중요하다

**T04 ~을 통해**
- 고칠 때: "~로", "~해서", "~에서"처럼 문맥에 맞는 조사나 동사로 쓴다.
- 그대로 둘 때: 실제로 무엇을 거쳐 지나가는 경로. "프록시를 통해 접속한다"는 둔다.
- [원문] 이번 기회를 통해 → 이번 기회에 (김순영 2012)
- [작성] 자동화를 통해 배포 시간을 단축한다 → 배포를 자동화해서 시간을 줄인다

**T05 ~로부터**
- 고칠 때: "~에서", "~에게서"로 쓴다.
- 그대로 둘 때: 문법 오류는 아니다. 입말에서 드물 뿐이다. 바꿔서 어색하면 둔다.
- [원문] 부모의 종교로부터 벗어나고 싶다 → 부모의 종교에서 벗어나고 싶다 (강주헌 2012)
- [작성] 클라이언트는 서버로부터 응답을 수신한다 → 클라이언트는 서버에서 응답을 받는다

**T06 ~을 가지다 (have)**
- 고칠 때: "~이 있다"나 형용사 서술로 쓴다.
- 그대로 둘 때: 실제로 손에 쥐거나 소유하는 뜻.
- [원문] 아름다운 목소리를 가지고 있다 → 목소리가 아름답다 (김순영 2012)
- [작성] 이 API는 세 개의 매개변수를 가진다 → 이 API에는 매개변수가 세 개 있다

**T08 ~에 대해, ~에 관해**
- 고칠 때: 지우거나 "~을", "~에게"로 바꿀 수 있으면 바꾼다. 스크립트는 한 문단에 세 번 이상 나올 때만 잡는다.
- 그대로 둘 때: 서술어의 대상이나 목적을 나타낼 때 (법제처 문장편 p.182~184).
- [작성] 설정 파일에 대해 검증을 수행한다 → 설정 파일을 검증한다

**T09 조사 + 의 (~에의, ~로의, ~에서의, ~와의)**
- 고칠 때: 서술어를 살려 풀어 쓴다.
- 그대로 둘 때: "저자와의 대화"처럼 사전 용례로 굳은 말.
- [원문] 보험 또는 공제에의 가입은 각 자동차별로 하여야 한다 → 보험 또는 공제에는 각 자동차별로 가입하여야 한다 (법제처 문장편 p.181)
- [작성] 운영 DB로의 데이터 이관 시 주의 사항 → 운영 DB로 데이터를 옮길 때 주의할 점

**T10 ~의 경우**
- 고칠 때: "~은/는", "~이면"으로 쓴다.
- 그대로 둘 때: 여러 경우를 나눠 견줄 때. "대부분의 경우"처럼 굳은 말.
- [작성] 토큰의 경우 1시간 뒤 만료된다 → 토큰은 1시간 뒤에 만료된다

**T16 ~중에 있다**
- 고칠 때: "~하고 있다", "~되고 있다"로 쓴다.
- [원문] 일부가 도로로 사용 중에 있으나 → 일부가 도로로 사용되고 있으나 (국어원 지침 p.7)

**T17 ~ 대비**
- 고칠 때: "~보다", "~에 비해"로 쓴다.
- [작성] 기존 대비 처리 속도가 2배 향상되었다 → 처리 속도가 기존보다 두 배 빨라졌다

**T13 부사 "보다"** (출처 미확인, 이 스킬의 규칙)
- 고칠 때: 비교 대상 없이 "더"의 뜻으로 쓴 "보다"는 "더"로 쓴다.
- [작성] 보다 빠른 처리를 위해 → 더 빨리 처리하려고

**~에 한하여, ~없는 한** (스크립트 검사 없음)
- 고칠 때: "~에서만", "~으로만", "~없으면"으로 쓴다 (법제처 문장편 p.190~193).

## 3. 명사 중심 구조

**T19 명사 + 진행/실시/수행**
- 고칠 때: 동작을 나타내는 동사를 바로 쓴다.
- 그대로 둘 때: "회의를 진행한다"처럼 진행 자체가 동작일 때.
- [작성] 백업을 수행한다 → 백업한다. 점검을 실시합니다 → 점검합니다

**명사구 직역과 "-의" 남용** (스크립트 검사 없음)
- 고칠 때: "-의"가 겹치거나 명사가 셋 넘게 이어지면 동사로 푼다.
- 그대로 둘 때: 명사가 이어져도 짧고 구조가 분명하면 둔다 (법제처 문장편 p.171).
- [원문] 영화는 한국 전통의 아름다운 재현이었다 → 영화는 한국의 전통을 아름답게 재현했다 (김정우 2012)
- [원문] 시행 과정에서의 문제점의 분석이 필요하다 → 시행 과정의 문제점을 분석해야 한다 (법제처 문장편 p.180)
- [작성] 사용자 인증 토큰 만료 시간 설정 변경 방법 → 사용자 인증 토큰의 만료 시간을 바꾸는 방법

**복수 "-들"** (스크립트 검사 없음)
- 고칠 때: 영어 복수형을 기계적으로 "-들"로 옮기지 않는다.
- [원문] 새로운 아이디어들과 방법들 → 여러 가지 남다른 생각과 방법 (김순영 2012)

## 4. 판단과 강조

**T07 ~하는 것이 필요하다**
- 고칠 때: "~해야 한다"로 쓴다. "요하다", "필요로 하다"는 "필요하다"로 쓴다.
- 그대로 둘 때: "~할 필요가 있다"는 법제처가 바꿀 말로 권하는 표현이다. 그대로 둔다.
- [원문] 단체에서 필요로 하는 기술 전문 인력 → 단체에 필요한 기술 전문 인력 (국어원 지침 p.7)

**T18 ~하는 것이 좋다/중요하다/권장된다 (It is recommended)**
- 고칠 때: 뜻에 따라 나눈다. "좋다", "바람직하다", "권장된다"는 권고라 "~하기를 권한다"로 쓴다. "중요하다"는 "~이 중요하다"처럼 대상을 주어로 쓴다. "필수다", "요구된다"는 의무나 필요 조건이라 "~해야 한다"로 쓴다.
- 권고를 의무로 올리거나 의무를 권고로 낮추지 않는다.
- 그대로 둘 때: "~해 주시기 바랍니다"는 정중한 요청이다. "~하기를 권한다"로 바꾸지 않는다.
- [작성] 경로를 명시적으로 지정하는 것이 권장됩니다 → 경로를 직접 지정하기를 권합니다

**T11 ~것으로 예상된다, ~것으로 기대된다** (스크립트 검사 없음)
- 고쳐 쓸 때: 확신 정도를 바꾸지 않는다. 그대로 두거나 "~할 것으로 예상합니다"처럼 주체를 살려 쓴다. 뜻을 정확히 옮기기 어려우면 원래 표현을 둔다.
- 새로 쓸 때: 근거의 확실성에 맞춰 쓴다. 근거 없는 효과는 쓰지 않는다.
- [작성] 처리 속도가 대폭 향상될 것으로 기대됩니다 → 처리 속도가 크게 빨라질 것으로 기대됩니다

**비교와 최상급** (스크립트 검사 없음)
- "가장", "더", "~ 중 하나"가 나타내는 비교 정도와 범위를 그대로 둔다. "가장 효과적인 방법", "가장 효과적인 방법 중 하나"는 그대로 쓴다.
- 문체를 고치려고 "특히 효과적이다"처럼 정도를 낮추지 않는다.

**T14 ~하기 위함이다**
- 고칠 때: 목적을 문장 앞에 "~하려고"로 쓴다.
- [작성] 이는 보안을 강화하기 위함입니다 → 보안을 강화하려는 것입니다

**T15 ~에 다름 아니다, ~라고 하는** (출처 미확인, 이 스킬의 규칙)
- [작성] 이 오류는 설계 결함에 다름 아니다 → 이 오류는 설계 결함이다
- [작성] 재시도라고 하는 기능을 사용한다 → 재시도 기능을 쓴다

**T22 "핵심은 ~이다" 분열문**
- 고칠 때: 문장 틀만 고쳐 주어와 서술어를 바로 잇는다. X와 그 중요성은 남긴다. "핵심은 사용자 경험의 일관성입니다"는 "사용자 경험의 일관성이 중요합니다"로 쓴다.
- 근거: 한국어 humanizer 저장소(im-not-ai)의 자체 실측에서 AI 글에 약 10배 많았다. 독립 검증은 없다. 문체 취향이 개입하는 이 스킬의 선택이다.
- [작성] 핵심은 롤백 속도입니다 → 롤백 속도가 가장 중요합니다
- [작성] 필요한 것은 명확한 기준이다 → 명확한 기준이 필요하다

**"할 수 있다"** (스크립트 검사 없음)
- 고칠 때: "이를 통해 ~할 수 있다"처럼 효과를 흐리게 말할 때만 고친다.
- 그대로 둘 때: 실제 가능성이나 허용을 말할 때. 규격 문서에서는 비강제라는 법적 뜻이 있다. 기계적으로 단정형으로 바꾸지 않는다.

## 5. 연결과 흐름

**S2 연결 어미 사슬**
- 고칠 때: 연결 어미가 거듭되어 주어와 서술어의 호응, 동작 순서, 조건이 걸리는 범위가 흐려지면 부연을 본문에 풀거나 문장을 나눈다.
- 그대로 둘 때: 사슬이 길어도 뜻이 분명한 문장. 짧다는 이유만으로 나누거나 합치지 않는다. 스크립트는 연결 어미가 세 번 이상인 문장을 후보로만 띄운다.
- [원문] A형은 포진성 구협염과 수족구병을 일으키며, B형은 심근염과 흉막통을 유발하며, 사람이 유일한 숙주임 → A형은 포진성 구협염과 수족구병을 일으키며, B형은 심근염과 흉막통을 유발함. A, B형 모두 사람이 유일한 숙주임. (국어원 지침 p.13)
- [작성] 사용자가 파일을 올리면 서버가 이를 검증하고, 실패하면 오류를 반환하며, 성공하면 저장하고 알림을 보낸다 → 사용자가 파일을 올리면 서버가 파일을 검증한다. 검증에 실패하면 서버는 오류를 반환한다. 성공하면 파일을 저장하고 알림을 보낸다.

**S3 접속어 남용**
- 고칠 때: 같은 접속어가 여러 문장 머리에 습관처럼 이어지면 줄인다. 번역문은 "그러나"를 지나치게 쓴다 (김정우 2012).
- 그대로 둘 때: 인과, 조건, 대조, 추가 관계를 분명히 하는 접속어. 국어원 지침도 적절한 접속어로 문장을 이으라고 한다.
- [작성] 설치가 끝났다. 그리고 서비스를 시작한다. 그러나 먼저 포트를 확인해야 한다. 또한 방화벽도 확인한다 → 설치가 끝났다. 포트와 방화벽을 먼저 확인한 뒤 서비스를 시작한다.

**T21 A, B, 그리고 C**
- 고칠 때: "A, B, C"나 "A와 B, C"로 쓴다.
- [작성] 구성 요소, 데이터 흐름, 그리고 장애 대응을 설명한다 → 구성 요소와 데이터 흐름, 장애 대응을 설명한다

**T23 메타 담화**
- 고칠 때: "앞서 설명했듯이", "결론적으로", "다시 말해"처럼 글의 진행을 알리는 말을 지우고 내용을 쓴다.
- 근거: 토스 테크니컬 라이팅 가이드.

**주술 호응** (스크립트 검사 없음)
- 고칠 때: 주어와 서술어만 이어 읽어 말이 되게 고친다.
- [원문] 세금 신고를 위해서는 → 세금 신고를 하기 위해서는 (국어원 지침 p.25)
- [작성] 이 문서의 목적은 배포 절차를 설명한다 → 이 문서는 배포 절차를 설명한다

**이중 부정** (스크립트 검사 없음)
- 고칠 때: 부정의 범위와 확신 정도가 같을 때만 긍정문으로 쓴다 (법제처 문장편 p.157).
- 그대로 둘 때: 가능성을 남기는 표현. "적용되지 않는 것은 아니다"를 "적용된다"로 바꾸면 보장이 된다. 뜻이 모호하면 원문을 둔다. 의도한 강조도 둔다.
- [작성] 이 옵션은 끄지 않으면 안 된다 → 이 옵션은 꺼야 한다

## 6. 중복과 군더더기

스크립트 검사는 없다. 쓴 뒤에 읽으며 지운다.

| 고칠 표현 | 고친 표현 | 출처 |
|---|---|---|
| 과반수 이상 | 과반수 | [원문] 국어원 지침 p.8 |
| 약 500여 곳 | 약 500곳, 500여 곳 | [원문] 국어원 지침 p.8 |
| 제출 유무 여부 | 제출 여부 | [원문] 국어원 지침 p.8 |
| 반드시 필요함 | 필요함 | [원문] 국어원 지침 p.8 |

## 7. 줄표와 장황한 부연

LLM 글에 자주 보이는 모양이다. 필요한 부연은 먼저 본문 구조에 넣는다. 호응이나 범위가 흐릴 때만 새 문장으로 나눈다. 앞말을 되풀이하는 말이면 지운다. 부호만 괄호나 쌍점으로 바꾸지 않는다. 줄표의 허용 범위와 근거는 [문장 규칙 8.2](rules.md#8-문장-부호와-길이)를 따른다.

**P1 줄표와 그 대용**
- 찾는 모양: —, ―, ㅡ, 엔 대시(–), 하이픈 두 개(--), 띄어 쓴 하이픈( - )
- 그대로 둘 때: 문장 규칙 8.2의 부제 예외. 코드와 명령어 안의 하이픈은 문장 부호로 검사하지 않는다.

| 모양 | 고칠 표현 | 고친 표현 |
|---|---|---|
| 줄표 두 개로 끼운 말 | 응답이 빨라지고 — 특히 읽기가 많을 때 — 원본 서버의 부하도 준다 | 응답이 빨라지고 원본 서버의 부하도 준다. 이 효과는 읽기가 많을 때 특히 크다. |
| 문장 끝에 붙인 결론 | 원인은 하나였다 — 연결 수 초과다 | 원인은 연결 수 초과 하나뿐이었다. |
| 줄표로 끌어낸 목록 | 세 가지를 본다 — 속도, 비용, 안정성 | 속도, 비용, 안정성을 본다. |
| 줄표로 강조한 대조 | 캐시는 강력하다 — 하지만 만능은 아니다 | 캐시는 강력하지만 만능은 아니다. |
| 목록의 "용어 - 설명" | **빌드** - 코드를 묶는다 | 빌드는 코드를 묶는 작업이다. |

**T24 ", 즉"으로 다시 말하기**
- 고칠 때: 앞말을 다른 말로 되풀이하면 둘 중 하나를 지운다. 새 정보면 본문 구조에 넣는다.
- [작성] 배포 시간이 줄어든다, 즉 더 빨리 배포할 수 있다 → 배포 시간이 줄어든다.

**T25 문단 안의 "결론:", "핵심:"**
- 고칠 때: 쌍점으로 결론을 끌어내지 말고 문장으로 쓴다.
- 그대로 둘 때: 목록 항목과 표의 "항목: 값".
- [작성] 결론: 캐시는 읽기 위주 서비스에 맞다 → 캐시는 읽기 위주 서비스에 맞다.
