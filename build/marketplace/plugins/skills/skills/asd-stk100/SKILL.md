# ASD-STK100

의미를 보존하는 간결한 기술 한국어다. ASD 공식 표준은 아니다.

## 공통 원칙

- 문체는 사용자 지시, 기존 문서, “~합니다”체 순으로 선택한다.
- 사실·조건·범위·부정·비교·시제·확신 정도를 보존한다. 권고·의무·가능성·계획·목적을 서로 바꾸지 않는다. 모호한 뜻은 추측하지 않는다.
- 자연스러운 표현은 유지한다. 고칠 곳이 없으면 원문 그대로 낸다. 문장은 호응이나 조건이 흐릴 때만 나누고, 부연은 본문에 넣는다. 괄호에는 짧은 값만 두고, 줄표는 제목 뒤 부제에만 쓴다.
- 용어·변수 풀이와 본문·목록의 설명은 이름표 대신 문장으로 쓴다. 따로 둘 보충 설명과 위험 안내는 접두사 없는 `>` 블록으로 쓴다. 원문의 설명용 접두사에도 이 규칙을 적용한다.

## 작업 순서

1. 새로 쓸 때 현재 상태·영향·필수 조치·일정·API 명세는 제공된 정보만 사실로 쓴다. 일반 지식은 설명하고, 가정·제안은 그 성격을 밝힌다. 꼭 필요한 미정 값만 빈자리로 둔다. 번역·교정에서는 정보를 더하거나 빼지 않고 문단·단계 순서를 유지한다. 재구성은 요청받았을 때만 한다.
2. 필요한 참조만 읽고 쓴다. 경로는 이 파일이 있는 폴더 기준이다.
   - 새로 쓰는 모든 문서: [개발 문서](references/dev-docs.md) 6~7절에서 해당 종류의 규칙을 읽고 구성한다.
   - 절차·런북을 새로 쓸 때: [문장 규칙 5절](references/rules.md#5-절차문)을 읽고 단계마다 동작 하나와 확인 결과를 짝짓는다.
   - 코드·UI·숫자·날짜를 표기할 때: [개발 문서](references/dev-docs.md) 2~5절. 상대 날짜는 유지하고, 환산이 필요하면 기준일과 날짜·요일을 검증한다.
   - 번역투·접속어 후보가 나왔을 때: [번역투](references/translationese.md)의 해당 항목에서 고칠 때와 그대로 둘 때를 읽는다.
   - 어려운 단어를 바꿀 때: [단어 목록](references/word-list.md). 전문 용어는 문맥을 확인한다.
   - 문장 구성이나 부호를 판단하기 어려울 때: [문장 규칙](references/rules.md)의 해당 절.
   - 규칙만으로 문체·구성을 판단하기 어려울 때: [예시](references/examples.md)의 같은 종류. 상황과 사실은 복사하지 않는다.

## 점검과 완료 기준

3. 최종 본문에 `python3 "스킬경로/scripts/check_style.py" 파일경로`를 실행한다. 도구가 있는 환경에서는 실행 결과를 확인해야 완료다. 스킬경로는 이 파일이 있는 폴더다. 채팅은 파일경로 대신 `-`로 본문을 표준 입력에 전달한다. 셸에서 백틱·달러 기호가 실행되지 않게 전달한다. 실행 도구가 없으면 수동 점검한다.
4. 검사 결과를 받은 뒤 후보마다 해당 항목과 예외를 끝까지 읽고 고치거나 유지한다. 도구 출력이 잘렸으면 해당 항목을 다시 읽는다. 종료 코드 1은 후보가 있다는 뜻이며 0건으로 만들 필요는 없다. 입력 오류는 해결하고 재검사한다.
5. 원문과 최종본을 대조해 의미 보존, 주술 호응, 기술 설명의 동작 순서, 용어·문체 일관성을 확인한다. 새 절차문은 마지막 번호까지 각 단계가 [절차 규칙](references/rules.md#5-절차문) 5.1·5.4를 만족하는지 대조한다. 수정했으면 재검사한 뒤 최종 본문만 낸다. 변경 설명은 요청받았을 때만 덧붙인다.
