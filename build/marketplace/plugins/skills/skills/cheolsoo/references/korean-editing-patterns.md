# Korean editing patterns

이 문서는 금칙어 목록이 아니다. 표현이 실제 정보와 문서 기능을 수행하는지 확인하고, 불필요할 때만 고친다. 전문 용어, 법적 문구, 인용, 조직 표준과 장르 관습을 우선한다.

## 어휘와 번역체

| 관찰 대상 | 확인할 것 | 편집 방향 |
| --- | --- | --- |
| 낯선 어휘 | 독자와 장르에 필요한 말인가? | 뜻을 줄이지 않는 익숙한 말로 바꾼다. |
| 직역어 | 한국어에서 같은 관계를 자연스럽게 나타내는가? | 원어의 단어보다 주체·행동·수단·원인·결과를 옮긴다. |
| 추상 동사 | `제고·견인·강화·확보·제공`이 실제 변화를 설명하는가? | 누가 무엇을 어떻게 바꾸는지 쓴다. |
| 피동·명사화 | 책임 주체나 행동을 가리는가? | 주체를 확인해 능동적인 동사로 푼다. |
| 완충 표현 | `~할 수 있다·~로 보인다·~라고 할 수 있다`가 필요한 불확실성인가? | 확신도는 보존하고 겹치는 완충어만 줄인다. |

`가시성`, `정합성`, `얼라인먼트`, `레버리지`처럼 분야에서 쓰이는 말도 자동으로 지우지 않는다. 독자에게 더 직접적인 표현이 있으면 기능을 풀어 쓴다.

## 자주 반복되는 상투 구조

다음 표현은 AI 판정 신호가 아니라 **주의 표현군**이다.

| 표현군 | 편집 질문 |
| --- | --- |
| `또한·한편·따라서·결론적으로·종합하면` | 삭제해도 문장 관계가 분명한가? |
| `다양한·효과적인·혁신적인·체계적인·지속 가능한` | 무엇이 어떻게 그런지 근거가 있는가? |
| `중요한 역할·큰 의미·새로운 패러다임·미래를 만들어가다` | 독자가 사용할 정보가 있는가? |
| `단순히 ~를 넘어·~뿐만 아니라` | 실제 대조나 확장이 있는가? |
| `이 글에서는·살펴보자·주목할 점은` | 문서 자체를 설명하지 않고 바로 내용으로 갈 수 있는가? |
| 반복되는 서론·요약·결론 | 새 정보 없이 같은 주장을 다시 말하는가? |
| 3항 나열·대칭 문단·균일한 문장 길이 | 내용이 아니라 틀을 맞추기 위한 구조인가? |
| 과도한 헤딩·강조·불릿 | 독자의 탐색을 실제로 돕는가? |

근거 없는 평가어는 다른 상투어로 바꾸지 않는다. 문장에 행동·주체·수치·조건·근거가 없고 삭제해도 원문 사실이 빠지지 않으면 문장을 뺀다. 예를 들어 앞 항목을 반복할 뿐인 `이를 통해 혁신적이고 지속 가능한 미래를 만들어갈 수 있음`은 새 목표나 근거가 없으면 삭제한다. 필요한 주장이라면 작성자에게 근거를 묻는다.

## 한영 표기·괄호·기호

1. 한국어만으로 뜻이 충분하고 약어를 다시 쓰지 않으면 한국어 대표 표기 하나만 쓴다.
2. 약어를 뒤에서 다시 쓰면 첫 등장에만 한국어와 약어를 병기한다.
3. API·제품·표준의 공식 이름이나 검색 식별자가 필요하면 원어를 남긴다.
4. 괄호 안팎의 같은 말은 한 번만 쓴다. `OAuth 2.0(OAuth 2.0, RFC 6749)`은 `OAuth 2.0(RFC 6749)`으로 정리한다.
5. 문장을 끝낸 뒤 같은 내용을 반복하는 괄호는 본문에 합치거나 뺀다. 출처·단위·약어·법적 조건은 남긴다.
6. 일반 산문의 `A + B`는 `와/과`, 수단, 결합, 인과 등 실제 관계로 푼다. 수식, 코드, 등급, 제품명, C++ 같은 고유 표기는 보존한다.

## 다국어 원문·문자 품질

일본어 등 외국어 자료로 한국어 글을 쓸 때는 원어의 어휘·피동형을 무조건 문제 삼지 말고, 원문의 주체·행동·조건·확신도가 한국어에서 제대로 전달되는지 확인한다. 자료 없이 작성된 문장의 어색함을 근거 없이 특정 언어의 번역투라고 단정하지 않는다.

최종 한국어 본문에서 아래 항목은 **검토할 후보**다. 인용, 외국어 예문, 고유명사, 법적 표기, 코드와 사용자가 요청한 다국어 문장은 유지한다.

| 현상 | 처리 |
| --- | --- |
| 뜻밖의 히라가나·가타카나 또는 장음부호 `ー` | 한국어로 쓸 자리인지 문맥을 확인하고, 뜻을 알 때만 고친다. |
| 한자 | 한국어에서도 쓸 수 있다. 문자만으로 일본어 혼입이라 판정하지 않는다. |
| `�` 또는 알아볼 수 없는 음절 | 원문·저장된 출력·화면 중 어디서 생겼는지 살핀다. 손실된 원문을 추측해 복원하지 않는다. |
| 한글 자모가 분리돼 보임 | 저장된 문자와 화면 표시를 구분한다. 정규화 차이일 수 있으며, 모든 자모를 오류로 취급하지 않는다. |
| 같은 낱말·음절의 무의미한 반복 | 의미·문맥에 맞게 재검토하되 인코딩 오류로 단정하지 않는다. |

## 모호한 내용

| 모호함 | 처리 |
| --- | --- |
| 주변 문맥으로 한 의미만 성립 | 그 의미를 선명하게 쓰고 의미 앵커를 재확인한다. |
| 작성자 의도, 내부 조직·정책·수치 | 웹에서 추측하지 말고 사용자에게 묻거나 모호함을 표시한다. |
| 인과·평가 주장에 근거가 없음 | 검색 결과로 새 주장을 만들지 말고 근거를 요청하거나 표현을 줄인다. |

## 최종 점검

- 상투 표현을 줄인 뒤 정보가 빠지지 않았는가?
- 명사열 때문에 주체·행동·조건이 가려지지 않았는가?
- 작성자 의도나 내부 정보를 추측해 채우지 않았는가?
- 원문 인용은 보존하면서 뜻밖의 외국어 문자·깨진 글자·무의미한 반복을 확인했는가?
- 수치·이름·인용·부정·인과·조건·불확실성이 그대로인가?
