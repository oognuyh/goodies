# Cheolsoo

## Overview

한국어 글을 처음 쓸 때는 명료하게 쓰고, 다듬을 때는 같은 기준으로 필요한 부분만 고친다. 독자·목적·문서 유형에 맞추되 사실과 작성자의 의도를 지킨다.

## When to use

한국어로 글이나 문서를 작성·윤문해 달라는 요청, 외국어 자료를 바탕으로 한국어 글을 써 달라는 요청에 적용한다. 사용자가 `철수`/`cheolsoo`를 명시해 한국어 답변을 요청한 경우에도 적용한다. 단지 한국어로 질문하거나 답하는 일반 대화, 번역만 하는 요청, 코드·Mermaid 작성에는 자동 적용하지 않는다.

## References

- **윤문·교정:** 공통 기준인 [`references/korean-editing-patterns.md`](references/korean-editing-patterns.md)를 끝까지 읽는다. 새 글은 외국어 원문·어휘·표기 판단이 필요할 때 관련 항목을 읽는다. 표현 목록은 금칙어가 아니다.
- **개조식·공문서 형식:** 항목 구조나 기관 양식을 판단할 때만 [`references/structured-documents.md`](references/structured-documents.md)를 읽는다.
- **사실 확인:** 사용자가 요청했거나 표현을 고치려면 공개 사실을 판별해야 할 때만 [`references/fact-checking.md`](references/fact-checking.md)를 읽는다. 표현만 다듬을 때 검증을 자동으로 추가하지 않는다.

## Workflow

1. **범위와 독자를 정한다.** 새 글인지, 윤문인지, 진단만 할지 구분한다. 명시된 독자를 우선하고 없으면 문서 유형·목적·전달 경로에서 추론한다. 독자와 문서 유형에 따라 결과가 크게 달라질 때만 묻는다.
2. **사실 경계를 확인한다.** 주어진 자료에서 주장, 수치, 이름, 인용, 부정, 인과, 조건, 불확실성·확신도와 필수 서식을 파악한다. 새 글에서도 출처에 없는 사실이나 근거를 만들어 넣지 않는다.
3. **작성하거나 다듬는다.** 새 글은 주체·행동·조건이 드러나게 목적에 맞춰 쓴다. 윤문은 문단 전개와 의미 관계부터 살피고 필요한 곳만 고친다. 외국어 자료는 단어·어순의 직역보다 원문의 의미 관계를 옮긴다.
4. **간단히 점검한다.** 아래 기준으로 결과를 읽고 원문이 있으면 대조한다. 한국어 본문에 뜻밖의 가나·깨진 문자·무의미한 반복이 있는지도 살피되, 인용·고유명사·코드·의도한 다국어 내용은 보존한다. 원문부터 손상된 문자는 추측해 복원하지 말고 확인을 요청한다.
5. **요청한 형태로 낸다.** 새 글은 본문만, 윤문은 기본적으로 윤문본과 짧은 변경 요약을 낸다. 본문만·진단만 등 사용자가 지정한 형식을 우선한다. 파일은 명시적으로 요청받은 경우에만 수정한다.

## 작성·윤문 기준

- **충실성:** 주어진 사실·조건·불확실성과 작성자의 의도를 지킨다.
- **적합성:** 독자와 문서 유형에 맞는 용어·격식·구조를 고른다.
- **명료성:** 주체·행동·관계를 분명히 하고 불필요한 직역·상투적 반복을 줄인다.
- **절제:** 이미 좋은 문장은 유지하며, 문장마다 같은 틀이나 불필요한 서론·요약을 강요하지 않는다.

## Example

### Before

> 사용자 경험(User Experience, UX)의 제고를 위해 인증서 만료 알림을 추가해 가시성을 개선하고 운영 + 개발 간 얼라인먼트를 진행한다(매주 검토한다는 의미다).

### After

> 사용자 경험을 개선하기 위해 인증서 만료를 미리 파악할 수 있도록 알림을 추가하고, 운영팀과 개발팀이 매주 함께 점검한다.

## Guardrails

- 이미 적절한 표현은 짧게 보이도록 바꾸지 않는다. 수정량은 품질이 아니다.
- 잠정적 촉발 요인을 확정된 원인으로 바꾸거나 신중한 표현을 삭제하지 않는다.
- 한자만으로 일본어 혼입을 판정하지 않는다. 깨진 글자는 화면에서만 보이는지, 원문·저장된 출력에도 있는지 구분한다.
- 자연스러움을 위해 오류나 무작위 변이를 넣지 않는다. 탐지기 점수를 약속하거나 탐지기 회피를 기준으로 왜곡하지 않는다.
