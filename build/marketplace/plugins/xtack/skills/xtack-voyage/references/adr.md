# ADR decisions

Classify a decision as ADR-worthy when all three hold: reversal has meaningful cost or impact; real alternatives have materially different consequences; and a future maintainer needs the rationale to understand or revisit the choice. For a persisted format or event change, assess whether an older version can read newly written data and what rollback would require; an additive change can still have meaningful reversal cost. Apply the same three criteria rather than automatically requiring an ADR for every storage change. Routine choices stay with the coordinator. Honor explicit requests to record or independently assess other decisions without automatically applying the ADR council.

For a new ADR-worthy decision, assign at least two distinct native subagents relevant stakeholder perspectives or independent analyses. Give each the requested outcome, decision, alternatives, constraints, and available evidence; do not invent stakeholder preferences. The coordinator is not one of the two. Collect independent positions, compare evidence and dissent, run focused probes or seek clarification between agents when useful, then make and own the decision. Before marking a decision accepted or final, including in a draft ADR, wait for both actual responses and compare each counted stakeholder and attributed position with them; starting agents is not receiving their positions. Do not infer additional participants or consensus from your synthesis. Model diversity is optional; independent subagent contexts are required. If the host cannot provide two agents or their positions, leave dependent work blocked and continue independent work.

When original stakeholder responses need to be recoverable, determine before delegation whether the host can provide reopenable events when possible, then verify the actual event can be reopened. If this is unavailable or uncertain and the user and host permit writing and retaining evidence files at the chosen paths, you may give each stakeholder a distinct new permitted path outside the product target in its initial brief and ask it to write its complete response there and return the same body through the host. Compare each file with its complete actual return and inspect the host delegation and attribution separately; a file, digest or summary does not authenticate the author or prove independence. Honor read-only and content restrictions, existing files, links and host denials. A path check is not race-free isolation. If the original, comparison or provenance cannot be recovered, label summaries and report the affected assessment as unverified; do not launch duplicate stakeholders merely to retain a response.

Record every ADR-worthy decision in an ADR as it is made and before implementing dependent work, including in a design-only task. Include the question and context, alternatives and tradeoffs, chosen approach and evidence, consequences, verification obligations, and material dissent or risks. Reuse the project's existing ADR path and format; otherwise use `docs/adr/YYYY-MM-DD-<slug>.md`. Reuse an existing applicable ADR and preserve superseded decisions. An ADR does not confer permissions or replace a required product decision.

If the user's boundary or the host prevents obtaining the required positions or recording the ADR, continue permitted investigation and report evidence, alternatives, and any clearly provisional recommendation. Identify the missing positions or record; a response is not a recorded ADR. Do not present the formal decision as complete or proceed with dependent work. An investigation or options-only request can reach its requested stopping point, but a request for the formal decision or ADR remains incomplete.
