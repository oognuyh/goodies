# Voyage delegation

When host-specific discovery, delegation, continuation, or recovery of session evidence matters, consult the relevant guide for [Codex](adapters/codex.md) or [Claude Code](adapters/claude-code.md), then verify the capabilities actually available in the session. For a continuing or interrupted goal, unavailable store reads, multiple revisions, or a prerequisite reclassified as incomplete or unverified, follow [goal recovery](goal-recovery.md) before dependent edits. Reassess identity, evidence and the current target; if they cannot be established, report the affected gap rather than inventing a successful recovery.

When independent workers may update the same goal, identify each worker's contribution, the goal identity and the permitted boundary. When using the bundled store, provide its accessible path and JSON-on-stdin invocation, or point workers to the [goal store guide](../scripts/GOAL.md). When practical, include a runnable `show` example for the identified goal; serialize and quote task values safely. If the handoff includes a command and its JSON input, explicitly identify stdin as the input location. Do not freeze a concurrently owned unit at its handoff-time status; preserve actual dependency requirements and later authorized changes. Have it inspect the current record, preserve other workers' current contributions unless authorized steering or reassessment requires changes, and reload and reconcile after a conflict. The store replaces supplied arrays; it does not merge contributions automatically.

For an independent reviewer or ADR stakeholder, start a fresh context without the implementer's conversation (for example, `fork_turns: none` or `fork_context: false` when supported by the current Codex tool). Supply the actual outcome, requirements, target, constraints, and relevant evidence explicitly. Provide the original request or its accessible source and actual later steering directly when available. Avoid rewriting those requirements into a second purported original in the handoff; label any necessary interpretation as a summary, and check it for added work or omitted restrictions. When choosing a review context, account for access to the actual target, including uncommitted changes and required evidence: an isolated worktree may contain only the committed baseline. A separate context can review the shared workspace when permitted; if access is uncertain, ask the reviewer to verify the target and report unavailable inputs. Do not bypass read boundaries or assume the reviewer saw inaccessible files. For a recovered review, establish separation from an actual delegation event or other independently observed provenance; a review, handoff or goal record's own assertion is not enough. If separation cannot be established, obtain a fresh independent review when permitted or report it unverified; do not claim independent review or stakeholder analysis.

For a delegated review, give the reviewer each relevant acceptance criterion's actual ID and description, or an accessible source containing both. Route fingerprints alone do not contain the criterion descriptions. Identify the user's permitted project root separately from the delegate's current directory. A host-created worktree can start the reviewer in a different directory; when the actual target is permitted under all user and host read restrictions, name that target and the allowed root explicitly rather than ambiguously saying only "the current directory". This does not expand the user's boundary or override a host denial; if the target cannot be read, report the limitation and assess only the artifacts actually available.

When delegating work informed by a selected specialist, supply the relevant method and constraints or have the delegate load the specialist and confirm access. If the current session has observed a host tool error and a permitted workaround relevant to the delegated task, summarize both in the handoff without unnecessary sensitive details; do not assume the fresh context saw them. The delegate must verify that the workaround is allowed in its own context and must not bypass a denial. If a specialist cannot be loaded, provide the relevant instructions directly or report any resulting gap. A skill loaded by the coordinator is not necessarily loaded in a fresh delegate context; preserve the delegate's independent assessment.

When handing implementation to Forge after selecting the execution core, carry forward the actual core location, declared target, intended checks and permitted receipt location or reopenable host event. The implementer can then capture the first relevant post-change check through the core when supported instead of rerunning an unchanged success solely to create a receipt.

Track the actual delegate handle and use the host's wait or status mechanism for that same work when available and permitted; otherwise use available host results without inventing a status and report any required assessment gap. An observation timeout or a pending result alone is not a reason to start a duplicate review. If the user explicitly requests another context or a changed target, missing assessment, or specific review gap requires one, start it when permitted; if unavailable, report the affected gap.

When coordinating and no useful independent work remains, prefer a foreground review if the host supports it and the user's instructions and available time permit. For a background review, use its actual completion notification or supported status mechanism; invoking a new delegate with the same name may start another review rather than check the first.

If a delegate fails because its configured model is unavailable, inspect host-supported alternatives or configuration when permitted. Retry when new evidence or a configuration change makes success plausible; do not guess model aliases or launch a new delegate just to poll an existing one. If no supported alternative can be established, continue independent work and report any required review or stakeholder position as unverified.

For an independent review described as retrievable, or another original observation that must be recoverable, locate and reopen the actual output in an available, permitted event or preserve it verbatim in a permitted location and reopen that. Compare the reopened review and its attribution with the actual host return for that same reviewer before claiming it is the original; a path or label alone cannot establish the match. Rendered text that looks identical or equal parsed JSON does not establish an exact original; line-oriented writes can add a trailing newline. If a record and its referenced file both identify the reviewer, compare identifiers only when they share a kind and namespace or a mapping is established; report a mismatch, or report the comparison unverified when they cannot be related. Matching identifiers alone do not authenticate either record. Record its specific location in the goal or another permitted existing record or report; if this is unavailable, report the recovery gap. An agent name, generic reference to the current session, or summary alone does not identify the original output. Label summaries as summaries; do not label contents as an event identifier or copy contents the user forbids retaining. If required evidence cannot be identified or reopened, leave the affected criterion unverified. Retain other evidence only as needed for the work, without secrets or an additional automatic database.

When a recoverable review is needed and the user and host permit a report file, the independent reviewer may write its own report to a new permitted evidence path outside the reviewed product target and return it through the host. Give that path and permission explicitly; a read-only review request alone does not authorize the write. Check the actual path and applicable boundaries, including links; if its permitted location cannot be established, do not write it. A path check alone is not race-free isolation. Check the actual delegation, target, return and file. Before calling the file the original returned report, compare its contents with the complete returned report body and separately establish attribution from the actual host event; host metadata need not be part of the report body. A path or digest alone cannot prove that match or independence. If it cannot be written, reopened or compared, honor the boundary, label any summary as such and report the actual recovery gap rather than repeatedly reconstructing an original.

When the coordinator can inspect the actual return and permitted report directly, compare them without asking the reviewer to repeat a hash merely for confirmation. Ask for further review only when a substantive uncertainty requires it; a hash alone does not establish authorship or independence.

Bind a review to the target the reviewer actually inspected using the reviewer's own target evidence or independently observed host evidence around the review. Include the project contract documents used to derive the outcome, as well as relevant source, tests and protected inputs, in the declared target or establish their identity separately with actual host evidence. Merely including a file in a target does not authorize changing it. Do not copy the coordinator's current digest into a review record and imply that the reviewer confirmed it. If the reviewed target or relevant contract identity cannot be established, leave the affected review or criterion unverified.
