# Bugfix playbook

Use when the authorized result is to restore behavior after a defect. Investigate the actual path and existing contract, scope the failure, and establish the expected outcome without taking the current implementation as its own specification. Use `xtack-trace` when a focused diagnosis helps. Reproduce a distinguishing failure at an appropriate public boundary when practical; record how the observed result differs from the expectation and distinguish a product defect from an invalid test or unavailable environment.

Assess actual impact and uncertainty using [risk policy](../policies/risk-and-approval.md). Resolve any ADR-worthy design decision before dependent changes. Select a small fix that addresses the observed cause and preserves neighboring behavior. When justified, add a meaningful regression that would have detected the failure; observe failure before the fix when feasible. Implement only the authorized change, then run the relevant basic checks and resolve failures.

For the risk level, obtain the required review against the actual target and original criteria and run separate regression/integration checks. Map each required outcome to evidence. Classify a blocking finding or failed check before repair. If it exposes an incorrect contract, inconsistent requirements, an insufficient design, or a superseded decision, return to the affected intent and design and reassess any ADR-worthy decision before dependent changes. Stay within the user's scope, and report unresolved intent or authority instead of silently changing the objective. Re-run affected checks and review after changes. If a required check or review cannot be established, report it as unverified. Complete only when the current fix meets every required condition; a reproduced defect alone completes a diagnosis request, not a fix request. Consider `xtack-wake` only for an observed recurring or consequential failure where prevention adds value.
